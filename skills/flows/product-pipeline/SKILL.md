# 产品交付流水线

## 五个阶段与交付物

目录统一为 `docs/deliverables/<slug>/`，`slug` 形如 `20261123-user-login`。

| 阶段 | 负责人 | 交付物 | 通过标准（准出） |
| --- | --- | --- | --- |
| 1 产品设计 | chief + `prd` | `01-prd.md`、`01-wireframe.md`、`01-interaction.md` | PRD 每条功能有可判定验收标准；线稿+交互稿齐备且通过交叉自检（见 `prd` skill）；非目标写明；假设单列 |
| 2 技术方案 | chief + `tech-design` | `02-tech-design.md` | 逐条给出可行性结论，无「需调整」「不可做」 |
| 3 开发实施 | `general` | 代码 + `03-dev-log.md` | 任务全部完成；类型检查/lint/构建通过 |
| 4 代码审查 | chief + `code-review` | `04-code-review.md` | 逐项审查清单全部通过；缺陷清单为空或已复审通过 |
| 5 测试回归 | `qa` | `05-test-plan.md`、`05-test-report.md` | 报告结论为「通过」；无未处理高优缺陷 |
| 6 记录归档 | chief + `archive` | `06-record.md` + `docs/README.md`「需求索引」追加一行 | 决策与遗留项可追溯；索引入口正确 |

**判断真实进度靠文件，不靠记忆**：先用 glob 查 `docs/deliverables/<slug>/` 下已有哪些交付物，文件不存在就说明该阶段没做过。阶段 1、2、4 必须由同一个执行者（chief）完成：1/2 之间要来回修订同一份 PRD；4 的审查者必须独立于实现者 general。

## 门禁（顺序不可逆）

```
01-prd.md + 01-wireframe.md + 01-interaction.md 齐备、交叉自检通过且用户确认  →  才能做技术方案
技术方案有可行性结论且全部「可做」  →  才能派 general
03-dev-log.md 任务完成   →  才能进入代码审查
04-code-review.md 结论=通过（缺陷已修复并复审） →  才能派 qa
05 报告结论=通过          →  才能归档
```

每道门禁都对应一个具体风险：没 PRD 就开工，开发会自己定义需求；带「需调整」进开发，中途必然返工；没 dev-log 就审查，改了什么无从核对；没审查就测试，实现质量问题会被当成功能缺陷或被漏过；报告不通过就归档，缺陷会被埋进历史。所以门禁不是形式主义，跳过任何一道都会在下个阶段付代价。

### 可行性回退（关键）

技术方案阶段必须逐条对照 PRD 功能编号给出结论：

| 功能 | 可行性 | 依据 | 若不可行的替代 |
| --- | --- | --- | --- |
| F1 | 可做 | 现有模块可直接扩展 | — |
| F2 | 需调整 | 现有字段无法支撑，需加迁移 | 把验收标准 AC2 改为… |
| F3 | 不可做 | 依赖的第三方接口未提供 | 本期砍掉，列入非目标 |

只要出现「需调整」或「不可做」：

1. 回到 `01-prd.md` 修订对应功能或验收标准
2. 重新走技术方案评审
3. 不把未解决的可行性疑问留给开发阶段

这是防止「产品拍脑袋、开发接不住」的唯一机制，不能省略。

## 每阶段执行模板

1. **进阶段前**：先读目标目录与相关源码目录的 `README.md`，按文件索引和关联筛出要读的文件；再读上游交付物 + 筛选出的代码，列出本次要解决的问题。
2. **执行**：只由该阶段的负责人产出，不越权。
3. **出阶段**：产出文件 → 自检清单 → 汇报「阶段/产出/待确认/下一步」。
4. **归档**：每个门禁通过后追加一条记录，不用等全部做完。

## 小需求的裁剪

单文件、无新接口、无数据变更的改动，可合并阶段 1+2，但必须仍产出：

- 一段需求与验收标准（写进 `02-tech-design.md` 顶部）
- 可行性结论与影响面、回归范围

只在用户明确说「这只是临时验证」时，才允许不写任何文档。

## 并行与拆分

- 一个 slug 对应一个需求；大需求按子域拆成多个 slug，用 `docs/README.md` 串起来。
- 阶段 3 可并行启动多个 `general`，但每个必须拿到不重叠的文件范围，否则串行。

## 与工具链的关系

- 编码规范、技术栈、目录约定来自 `workspace` 与各技术栈规范 skill，不在本流程重复。
- 设计工具与外部 CLI 见工具链 skill。
- 无人值守跑阶段时用 `opencode run`，每个只给一个阶段目标，让它读交付物文件。
