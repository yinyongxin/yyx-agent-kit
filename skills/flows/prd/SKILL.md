# PRD 模板

目标产出：`docs/<slug>/` 下三份——`01-prd.md`（做什么）、`01-wireframe.md`（页面上显示什么）、`01-interaction.md`（页面怎么联动）。slug 用 `YYYYMMDD-简短英文名`，用户给了就用用户的。三份都是 Markdown 结构描述 + Mermaid 图，不做精细视觉设计。

PRD 的价值不是把想法写漂亮，而是让技术方案、开发、测试引用同一组编号和验收标准。所以编号稳定、每条标准可判定，比文采重要——后面每个阶段都靠它对齐。

## 文件结构（照抄顺序）

```markdown
# <需求名> PRD

## 1. 背景与目标
为什么要做；不做会怎样；一句话目标（含可衡量指标）。

## 2. 用户与场景
目标用户、使用场景、当前替代方案与痛点。

## 3. 范围
### 3.1 本期做
### 3.2 明确不做（非目标）
### 3.3 依赖与假设

## 4. 功能清单
| 编号 | 功能 | 优先级 | 说明 |
F1 为最高优先级，编号稳定，后续文档一律引用编号。

## 5. 详细需求
每个功能一节：触发入口、主流程、分支与异常、状态流转、权限、数据字段与校验规则、错误提示文案。

## 6. 验收标准
按功能编号，每条用 Given/When/Then，必须可判定。

## 7. 非功能要求
性能、容量、兼容性、安全、隐私（写具体阈值，如「首屏 < 1.5s，P95」）。

## 8. 埋点与度量
事件名、触发时机、关键属性。

## 9. 待确认问题
编号 + 问题 + 默认假设 + 影响面。
```

## 验收标准写法

一条 AC 要让测试能直接照着写出用例。如果一句话里出现「流畅」「友好」「优化一下」这类形容词，就无法判定，必须换成可观测的结果。

差：「登录体验要流畅」。

好：

```
F1-AC1
Given 已注册用户位于登录页
When  输入正确手机号与密码并提交
Then  3 秒内进入首页，且本地保存登录态，刷新后仍保持登录
```

```
F1-AC2
Given 连续 5 次密码错误
When  第 6 次提交
Then  提示「账号已锁定，10 分钟后重试」，且 10 分钟内正确密码也拒绝登录
```

## 编号为什么必须稳定

功能编号是后续技术方案（可行性结论）、开发日志、测试用例、归档记录的唯一连接键。改一次编号，下游四份文档全部要同步改，而且极容易漏。所以编号只增不改；需求废弃时保留编号并标注「已废弃」，不要回收再用。

## 自检清单

- [ ] 每条功能都有至少一条验收标准，能写出测试用例
- [ ] 边界条件写明：空、超长、特殊字符、0、并发、重复提交
- [ ] 权限矩阵覆盖：未登录、普通用户、管理员
- [ ] 状态机闭合：每个状态有进入条件、退出条件、非法流转的处理
- [ ] 非目标明确，防止开发自行扩展
- [ ] 所有假设单列，不与需求混写
- [ ] 没有「等等」「类似地」「优化一下」这类无法执行的表述

## 三件套交付物

| 文件 | 回答什么 | 主要形式 |
| --- | --- | --- |
| `01-prd.md` | 做什么、为什么、验收标准 | 功能编号 + Given/When/Then |
| `01-wireframe.md` | 页面上显示什么、区块怎么组织 | ASCII 布局图 + 区块/字段表 |
| `01-interaction.md` | 页面怎么联动、状态怎么流转 | 交互编号表 + Mermaid 图 |

线稿和交互稿是 PRD 的配套，不是精细视觉稿。编号与 PRD 功能编号（F1…）对齐；交互编号（I/G/E/Q）稳定，后续技术方案、开发、测试一律引用。

## 产出后交叉自检（强制）

写完三份后逐条检查，**不通过就先修再交付**——不要等用户指出矛盾：

1. **编号闭环**：结构图/表格里出现的每个区块 ID（W/U/A 等）都要有对应定义行；三份文档里的 F 编号含义一致。
2. **页面闭环**：交互里跳转到的每个页面，都要在线稿的「页面范围」里出现；没有的补上或标注「本期不实现」。
3. **状态唯一**：同一条件在两份文档里只能有一种表现（如「未入驻时显示什么」）。用 `grep` 搜关键词（如 `隐藏 A`、`counts`）核对，禁止一处说可见、一处说隐藏。
4. **状态机闭合**：每个非终态有进入和退出条件；Mermaid 里同一条转换边不重复写；超时、并发、取消都有明确归属。
5. **Mermaid 可渲染**：节点标签含 `?`、逗号、括号、中文标点时用引号包住；`alt/else/end`、`note … end note` 成对；每张图能独立渲染。
6. **中文一致**：说明文字用简体中文，不夹杂 `counts`、`TODO` 等英文词（标识符、事件名、技术术语除外）。
7. **规则有落点**：全局规则（如 G4 下拉刷新）必须在交互明细里有对应条目，否则删规则或补条目。

自检后再汇报「阶段 / 产出 / 待确认 / 下一步」。
