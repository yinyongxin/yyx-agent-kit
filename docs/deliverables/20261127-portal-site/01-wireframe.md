### 3.3 W3 核心特性（6 项）

| 图标文字 | 标题 | 描述 |
| --- | --- | --- |
| pipeline | 五阶段交付流水线 | PRD → 技术方案 → 开发 → QA → 归档，每阶段都有门禁 |
| skills | 规范即代码 | workspace / nestjs / react / next 按栈拆分，description 自动加载 |
| agents | 两个角色，各司其职 | chief 编排门禁，qa 独立测试且禁止改业务代码 |
| docker | 项目自包含环境 | PostgreSQL(pgvector) + Redis，容器/卷/网络带项目前缀 |
| cli | CLI 一键创建 | yyx-new 替换项目名与端口，pnpm dlx 即用 |
| auth | 租户与 RBAC 骨架 | tenantId 由 Prisma 中间件注入；NestJS 官方认证授权 |

### 3.4 W4 五阶段流水线

01 产品需求（01-prd.md）→ 02 技术方案（逐条可行性）→ 03 开发实施（03-dev-log.md）→ 04 测试回归（判定通过）→ 05 记录归档（05-record.md）。下方一行说明：方案不可行回 01 修订；测试不通过回 03 修复；qa 独立于实现者。

### 3.5 W5 技术栈规范（4 项）

workspace（pnpm / mise / monorepo / 端口 47xxx / Docker / 迁移）、nestjs（模块分层 / Prisma 多租户 / 官方认证授权）、react（Vite / Tailwind / Mantine / 路由）、next（App Router / Server Component / SEO / 共享包）。

### 3.6 W6 CLI 用法

终端块显示命令，下面参数表：项目名 / `-p, --path` / `--port-base` / `-f, --force`。

### 3.7 W7 FAQ

4 问：与直接让 AI 写代码的不同 / 是否必须用 OpenCode / 新项目配环境是否麻烦 / 能否接 SSO。答案为 PRD 中真实结论。

### 3.8 W8 最终 CTA

标题「从下一个项目开始，让交付有章可循。」+ 两按钮（npm 安装 / 阅读文档）。
